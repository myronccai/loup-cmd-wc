# Design: wc

## Overview

`main()` passes `runtime.args()` to `cli.app.run`, which parses the arguments
into `Options`, handles `--help` and `--version`, and calls
`commands.wc.run_wc`. `run_wc` reads and counts every input first, then
chooses the column width from all of them, as GNU wc does from `stat`, and
prints one line per input and the total.

## Modules

| Module | Contents |
|---|---|
| `source/main.loup` | entry point: `run(runtime.args())` |
| `source/appinfo.loup` | name, version, summary, exit statuses (usage errors are status 1, as in GNU wc) |
| `source/cli/args.loup` | `Options`, the `TOTAL_*` modes, `match_long`, `parse_total`, `parse_args` |
| `source/cli/usage.loup` | `usage()` help text, `version_line()` |
| `source/cli/app.loup` | `run()`: parse, help/version, run the command, map exceptions to status 1 |
| `source/commands/counts.loup` | `Counts`, `count_data` (one pass over the bytes), `sequence_length`, `decode`, `is_space`, `char_width`, `add_counts` |
| `source/commands/widths.loup` | `width_runs()`: the display width table, generated by `tools/gen_widths.py` |
| `source/commands/wc.loup` | `Input`, `selected`, `pad`, `column_width`, `format_line`, `show_total`, `run_wc` |

## Counting

`count_data` walks the input's `bytes` once, keeping a line count, a word
count, a character count, the current column and the widest line so far.

- Decoding follows glibc's UTF-8 `mbrtowc`, which GNU wc uses:
  `sequence_length` accepts 2- to 6-byte forms (glibc still takes the old 5-
  and 6-byte forms and code points above U+10FFFF) and rejects overlong forms
  and surrogates. A byte that does not start a character counts as a byte
  and as part of a word, but not as a character, and has no width.
- Words: a character in `is_space` (glibc's `iswspace` in UTF-8, plus the
  no-break spaces U+00A0, U+2007, U+202F, U+2060 that GNU wc adds) ends a
  word; anything else, controls included, continues or starts one.
- Line width: TAB moves to the next multiple of 8; `\n`, `\r` and `\f` end a
  line; other characters add `char_width`, a binary search over
  `width_runs()`.

Working on `bytes` rather than strings keeps the three lanes identical:
`loup run` and native builds iterate strings by their own rules, and Stage0
refuses text that is not UTF-8.

## The width table

`tools/gen_widths.py` asks glibc's `wcwidth()` (through Python's ctypes, in
`en_US.UTF-8`) for the width of every code point and writes the runs of equal
width to `source/commands/widths.loup`, about 2,000 (first code point, width)
pairs. Widths below 0 (controls, unassigned code points) become 0, as GNU wc
adds only positive widths. The table was made with glibc 2.42.

## Output

`column_width` follows GNU's `compute_number_width`: 1 when exactly one
count of one input is printed or under `--total=only`; otherwise the number
of digits of the summed sizes of the inputs that are regular files, and at
least 7 when an input that exists is not a regular file (a pipe, a terminal,
a directory). Loup has no `stat()`, so the size is the number of bytes read
and "regular file" is `io.fs.isFile`, which is `stat`-based. `format_line`
right-aligns each selected count with `pad` (`system.text.padStart` does not
link in a native build) and adds the name, except for standard input read
without operands. `show_total` applies `--total`.

## Differences from GNU wc

- Each input is read whole (no streaming reads in Loup 1.26.0, ROADMAP T2),
  so wc on an endless input never finishes, and memory grows with the input
  size.
- Characters, words and widths always follow UTF-8 rules, whatever the
  locale; GNU wc follows the locale (in the C locale it counts bytes as
  characters).
- Display widths come from glibc 2.42; a newer glibc may give new Unicode
  characters other widths.
- Messages quote like GNU in the C locale (`'x'`, never `‘x’`), and file
  names are never quoted (GNU quotes names that contain a newline).
- `--files0-from` is not implemented.
- A file that exists but cannot be read stops the native binary with the
  runtime's own `IoError` message and status 1 (no `stat()` to check
  permissions first, T1).
- `--version` prints one line.

## Error handling

A missing operand gives `wc: NAME: No such file or directory` and no line of
counts; a directory gives a line of zeros and then `wc: NAME: Is a
directory`, in GNU's order. Both set status 1 and count as zero in the total.
Usage errors come back from `parse_args` as `Err(message)`; `run` prints them
with the `Try 'wc --help'` line and returns 1.

## Testing

- `tests/args_test.loup`: default and selected counts, long options,
  `--total` values and prefixes, usage errors.
- `tests/counts_test.loup`: lines, words, bytes, characters, separators,
  bad bytes, `sequence_length`, `decode`, `is_space`, `char_width`, `-L`.
- `tests/wc_test.loup`: `pad`, `column_width` in each case, `format_line`
  order, `show_total`.
- `tests/app_test.loup`: exit statuses through `run()`.
- `tests/e2e.sh`: the native binary on files, pipes and standard input,
  compared byte for byte, including UTF-8, bad bytes, wide characters, column
  widths, every `--total` mode, errors and statuses.
